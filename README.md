# 星选助手（本地程序）

Windows / Python Tkinter 桌面程序，包含牛奶团购、团购配送、订单发货、对账分析、商品池和设置。

## 运行

安装 Python 3.13，运行 `python -m pip install -r requirements.txt`，然后 `python main.py`。
打包：`python -m PyInstaller --noconfirm 星选助手.spec`。生成的程序位于 `dist/星选助手.exe`。
个性化业务配置放在程序同级的 `config/` 文件夹；源码运行时位于项目根目录，打包运行时位于 EXE 同级。

## 微盟商品池

打开「商品池分析 → 微盟商品池」，填写微盟后台 Weimob Admin Skills 的 API Key，点击连接并保存。
选择商户及商城 / 门店，分页查询或按名称、编码搜索商品。双击商品，逐店搜索并核对商品 ID，折叠显示门店结果。
读取失败单独显示，可再次点击重试。名称搜索后核对 ID 不等同于完整分配关系接口，门店商品改名可能导致漏匹配。
可查看每条商品的完整原始 JSON。空字段显示「未返回」，不自动补零；商城与门店库存分别显示。

协议依据用户提供的 Weimob Admin Skills 1.0.1：`merchants`、`stores`、`goods`，网关为微盟 `wos-skills.weimob.com`。
仅使用该技能的 API Key，无需开放平台应用或 WOS access_token。
已接入门店原始返回中的最低、最高成本价；多规格商品显示成本区间。
支持导出当前页及已读取门店，也支持逐店全分页导出全部门店成本。Excel 保留商品ID、门店、编码、成本上下限、售价上下限、库存和查询时间；失败门店单列工作表。
「读取全部门店」将完整门店数据载入程序，按商品折叠各门店。支持门店名称、成本区间（区间相交）、有正成本/零成本/未返回、上下架筛选；名称和编码也参与本地筛选。「导出当前展示」导出筛选后的记录，工作表说明标注范围和条件。「导出全部门店成本」独立重新查询全部门店，不受当前筛选影响。
接口返回0保留为0，未返回成本留空；门店成本区间不等同于SKU明细。商品编辑尚未实现。
程序不自动下载或执行官方包的更新脚本。

API Key 保存于本机 `config/weimob_admin.json`，已排除 Git 跟踪。请勿把该文件、业务表格或带密钥的配置上传到 GitHub。
原有「门店导出合并」功能保留，可继续处理门店导出的完整字段。

## 两级商品状态

商城商品池控制是否禁售（商城查询返回的 `isCanSell`），门店商品控制上下架（门店的 `isOnline`）。商城禁售优先。
“读取全部门店”先读取商城全部商品，再按商品ID关联门店，分列显示商城禁售控制、门店上下架、两级状态。
未读到商城状态不推断为允许，商城行的门店上下架为不适用。两级状态允许不代表有库存、活动有效或必然能下单。
两套状态均可筛选，导出保留状态口径。全量读取期间数量变化、重复页或缺页不当作完整结果。

## 采购定价表

在“采购定价核对”导入 `.xlsx` / `.csv`，选择工作表、表头行以及列对应关系。支持供应商、供货价、核定售价、有效期、型号、品牌、单位、采购人、统一编码。
供货价与核定售价分开保存。支持 `2025.8.12-2026.8.11` 形式的有效期区间；到期日当天仍有效，空到期日待核对，不默认长期。
只还原工作簿实际合并单元格，不对普通空白前向填充。原始行、来源文件/工作表/行号和合并范围一并保留，错误记录不静默丢弃。
名称和型号用于推荐候选，编码一致也不跳过供应商及规格确认。用户确认后建立本地“采购行→门店商品”关联，一个采购行可对应多个门店。
过期、未生效、重复有效定价、缺失和多规格区间分别提示，不将含糊名称自动匹配当成核实结论。
可按品名/供应商、有效期、匹配状态筛选采购记录，再导出成本核对结果。统一编码为后续统一管理预留，但原商品编码可能是供应商码，不保证唯一。

## 活动价格（只读后台查询）

“活动价格核对”支持导入当前商户的浏览器 HAR：已清理 HAR 可离线导入已捕获响应；带登录信息的本机 HAR 可建立临时会话。
只允许在用户实测HAR中观察到的两条 `https://master.weimob.com` 读取路径：

- `/api3/mall/mgr/promotion/activityGoodsList`
- `/api3/mp/promotion/adapter/queryPromotionDetail`

不支持任意地址/命令执行，不跟随重定向，不调用修改/删除/发布接口。查询凭证仅在内存使用，退出即丢弃，重开需重新导入本机HAR；会话过期需登录后重新采集。原HAR仍由用户保存在本机，勿上传GitHub。
“一键读取活动全部商品”逐页校验总数和重复，失败不覆盖上次业务快照。离线部分响应明确显示已读取数/总数与采集时间。
活动SKU视图展示响应里的规格、成本、活动价、成本节点及来源；该SKU成本不冒充供应商门店成本。
门店核对视图按商品ID关联门店成本，并验证活动组织范围。当前适配实测的固定时间、指定门店范围；其他规则显示待核对，不猜测。
价格低于成本为活动价倒挂，低于可配置成本倍数为未达加价目标（默认1.15，加价率15%，并非毛利率15%）。多规格区间不跨规格判定倒挂。
展示叠加优惠提示，但不将活动基础价当作券后实付价。采购核定售价仅用于已确认关联且有效、唯一的采购记录。
当前筛选可导出Excel，保留来源节点、采集时间、完整性、状态和金额，商品/SKU编号作为文本，外部文本不执行Excel公式。

业务快照与本地匹配存于 `config/pricing_<商户>.json`（不含HAR请求头，已排除Git）。按商户隔离，刷新失败保留原快照。

## 验证

运行 `python -m unittest discover -v` 验证状态优先级、日期边界、合并单元格、保守匹配、分页一致性、只读接口白名单和导出类型。
